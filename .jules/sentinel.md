## 2024-05-15 - DOM-based XSS via innerHTML in Simulated Audit
**Vulnerability:** A High priority DOM-based Cross-Site Scripting (XSS) vulnerability was found in the `runSimulatedAudit` function. User-supplied inputs (`bizName`, `bizType`, and extracted location names) were directly interpolated into a template literal without sanitization and assigned to `resultArea.innerHTML = finalHTML;`. This allowed arbitrary JavaScript execution if a malicious payload was entered into the business name field.
**Learning:** Even in simulated frontend components, directly assigning unescaped template literals containing user inputs to `.innerHTML` creates an immediate XSS risk. Input sanitization must be performed before interpolation.
**Prevention:** Always escape user inputs (e.g., escaping HTML entities like `<`, `>`, `&`, `"`, `'`) before incorporating them into HTML strings that will be rendered via `innerHTML`, or alternatively, use safer DOM manipulation methods like `textContent` where HTML parsing is not required.
